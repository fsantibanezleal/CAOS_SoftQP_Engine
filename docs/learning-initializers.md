# SoftQP learned initializers

The R4 design defines two CPU float64 initializers, each followed by a pinned native solver and original-space evaluation. The engine implements the numerical and training primitives. Product orchestration supplies the phase-specific source readers, source and checkpoint admission, execution limits, checkpoint publication and held-out evaluation.

## Shared lift and original-space evaluation

`PreparedLearningProblem(problem, **units)` snapshots the original interval or peak problem and reuses the comparator's validated S/A/G lift. It retains physical and dimensionless matrices, lifted unit references and signed recovery. For diagonal unit maps `D_x` and `D_r` and objective unit `S_f`, the maps use `P_hat = D_x P D_x / S_f`, `A_hat = D_r^-1 A D_x`, and `q_hat = D_x q / S_f`. Physical warm starts use `x = D_x x_hat` and `y = S_f D_r^-1 y_hat`.

`PreparedLearningProblem.reference()` runs the independent three-backend reference rule and issues process-local `ReferenceEvidence` tied to its canonical transform. The issuance path checks all three exact backend identities, native statuses, independently evaluated original metrics, objective agreement and median. `as_dict()` produces a detached audit copy. Product orchestration supplies the whole-process deadline and controls any future cross-process reference re-admission. Native success is screened with lift and original-space feasibility, stationarity, complementarity, Fenchel diagnostics, dual repair and applicable epigraph diagnostics. An accepted result also needs an agreeing reference with a matching transform identity and a passing original objective gap. Results retain failed native flags and omit failure-path primal or dual buffers.

`backend_settings()` exports the effective binding defaults and fixed overrides for source registration. `InferenceBinding` carries the engine transform and numeric weights digests and the method-specific admitted normalizer or threshold. The product verifies the surrounding artifact provenance, complete head coverage, approved phase and selected checkpoint before constructing the binding. The solver checks the binding against the supplied problem, model and numeric values.

## L-1 fixed-point OSQP

`L2WSHead(n,m,seed)` supports the fourteen registered hard-lift dimensions. Parameter names are `hidden1.weight/bias`, `hidden2.weight/bias` and `output.weight/bias`. The layers are width 128, width 128 and width `n+m`, with ReLU on the first two. The input is the ordered triangle of `P_hat`, row-major `A_hat`, `q_hat`, the two bound vectors with absent sides encoded as zero, and two separate finite-side masks. `Normalizer.from_admitted` consumes the artifact-verified training mean and population scales. `Normalizer.fit` exposes the weighted fit for explicit phase-scoped arrays and software controls.

`FixedPointProblem` uses the differentiable Cholesky factors of the actual `P_hat + sigma I + A_hat.T R A_hat`, with scalar `R = 0.1 I` and `sigma = 1e-6`. The initial auxiliary value is `A_hat x_hat0`. One unrelaxed transition solves the linear system for `x`, projects `A_hat x + y_hat / 0.1` to the original dimensionless intervals, and updates the dual. Projection derivatives are one strictly inside an interval and zero at either endpoint and outside. Training computes the squared block-mean residual of transition six from state five, with gradients through all six transitions. Diagnostic K0 compares the initial state to its first transition.

`solve_osqp` predicts once, converts the two vectors to physical lifted units, and invokes stock OSQP 1.1.3 through `warm_start(x,y)`. Learned, cold and previous-vector controls rebuild the workspace each trial with the same scalar-rho, unrelaxed and unscaled settings. The C workspace regression checks independently reconstructed primal and dual iterates after each of six actual native solves with a controlled iteration limit, including an equality, nonzero initial duals and an out-of-box initialization.

## L-2 graph-guided DAQP

`PreparedLearningProblem.one_sided()` requires exact positive definiteness of the submitted lifted Hessian, using exact rational elimination within independent nonzero blocks. The graph uses dimensionless variables and canonical upper-form constraint sides. A two-sided inequality emits upper and lower rows in order, with recovery signs +1 and -1. A finite equality emits one immutable row. Variable features are `(q_hat,0,0,0)`. Constraint features are `(0,b_hat,equality,1)`. Signed nonzero Hessian entries define directed variable edges, and signed constraint entries define both cross-partition edge directions. Population normalization uses each graph alone.

`ActiveSetGNN(seed, positive_prior)` applies actual PyG 2.8.1 `LEConv` in widths 4, 128, 128, 1, with hidden LayerNorm and LeakyReLU of slope 0.1. The 52,098 parameters include the two norms. In each LEConv, the messages are `edge * (lin1(source) - lin2(target))`, with additive `lin3(target)`. Only `output_layer.lin3.bias` uses the training class log odds. The other biases are zero, including the weighted-message `output_layer.lin1.bias`.

`cold_labels` makes a fresh DAQP 0.10.3 call with the tight label settings and original equalities at sense 5. Labels require native acceptance, tight original-space and canonical acceptance, and agreeing transform-bound reference evidence. A finite inequality is positive if it is tight within `1e-7 * max(1,abs(b_hat))` and its signed upper multiplier exceeds `1e-7`. A loose inequality with multiplier magnitude at most `1e-7` is negative. The label reader consumes the solver-returned side multipliers directly. The pinned native result extractor already zeros wrong-sign hard mutable multipliers. Ambiguous inequalities, variables and equalities have zero loss mask. Class mass uses the frame's masked class fraction with the declared source/frame weight. The loss uses mean masked class-weighted softplus, implemented as a stable log-sum-exp. Empty masks retain an exact zero frame loss. Training requires both class masses and validation requires at least one unmasked node. [Pinned DAQP result extraction](https://github.com/darnstrom/daqp/blob/29a8987d8b9a596c1ab6acf84c17d38b068b73bc/src/api.c#L503-L522)

`calibrate` operates on calibration observations with thresholds 0.1 through 0.9. Prediction uses strict greater-than. It first aggregates confusion counts within each source using inverse frame count, then averages the source-level F1 with source weights. The larger threshold wins a tie. Held-out metrics use the graph's inequality mask for ambiguity coverage and the declared frame/node weights for PR, ROC, Brier and 10-bin ECE. Absent classes give undefined curves with counts.

`solve_daqp` passes its predicted sense vector to the public DAQP binding. Every equality stays at 5. Only native flag -6 causes a removal. The next removal is the globally lowest-scored predicted inequality, with canonical row ID and side order breaking ties. The attempt after eliminating all predicted inequalities is the only cold fallback. Native diagnostics include every sent flag vector, native flag, wall time, native setup and solve times, and removed row. On the exact synthetic NC14 input the pinned runtime already accepts the redundant predicted active set. The conditional removal order is checked by an explicit -6 callback; a contradictory immutable-equality case also exercises native -6 and terminal failure.

## Source batches, seed streams and numeric resume

`balance_sources` applies equal family, regime-within-family and source-within-regime weights. Each source's inputs are an ordered sequence of frames with equal weights within that source. Supply the complete admitted method population to compute source weights, then select a head's sources while retaining weights for conditional renormalization. Phase checks precede frame reads. Phase completeness and lazy artifact admission are product responsibilities.

`HeadTrainer` advances an explicitly supplied train/validation stream by one epoch. Each batch has whole source units. Individual frame gradients use their fixed fractions of the full epoch weight, with one AdamW step at the end of the source batch. The L-1 schedule uses 32 sources, decay 0.0001 and patience 20 at minimum improvement 1e-6. L-2 uses 8 sources, decay 0.01 and patience 5 at improvement 0.001. Both have learning rate 0.001, beta 0.9/0.999, epsilon 1e-8, and at most 100 epochs. Validation runs before any update and after each epoch. The best checkpoint is the lowest measured validation objective with ties going to the earlier epoch. A separately tracked significant improvement controls patience. Training history retains the weighted loss encountered during the optimizer steps, separate validation loss, optimizer steps, gradient diagnostics and order receipts.

Each parameter and epoch order uses its own generator under the R4 SHA-256 namespace and one seed from 41001/41002/41003. Allocations avoid advancing the global CPU RNG. Each parameter receipt records the exact named shape, initialization rule, local seed when applicable and raw tensor hash. `parameters.weight_bytes` and `load_weights` use checked little-endian float64 arrays in lexical parameter-name order. `training.NumericResume` consists of strict JSON identity and history bytes, numeric initial/current/best arrays, AdamW moments and the CPU epoch shuffle RNG bytes. The snapshot is bound by a length-delimited digest. Restoring recomputes order/history invariants and checks model, inputs, shapes, steps and RNG before applying the state. An interrupted epoch requires restoring the last complete snapshot before retry. The product controls atomic file persistence and full multi-head inventory.
