# Exact prospective simulator specification

This document closes the coefficient/distribution definition referenced by protocol.md. It is proposed mathematics, not implemented data. Independent review must accept these equations and their coverage before the frozen generator is coded/registered. No old problem byte stream or seed is read as a generation input.

## Common deterministic construction

Use the entropy streams and indices in protocol.md and NumPy's PCG64 generator created from each SeedSequence. Bounds are original-coordinate values; infinities are represented by null/masks in strict JSON. All computations/export use float64. Every generated matrix and source parameter is recorded and hashed. A source unit has independent coefficient RNG stream0 and operating-parameter RNG stream1; a trajectory uses stream2 for specified perturbations. No draw is conditioned on a candidate answer. All generic-QP quantities are dimensionless. The draw order below is part of the frozen implementation: coefficients first, operating variables second, no loop-dependent random calls during solver evaluation.

Generic PD constructor for n: draw an n-by-n iid normal matrix M, compute reduced QR with diagonal-R signs made positive, then calculate the temporary array `B=(Q*geomspace(1,kappa,n))@Q.T`, multiplied by a positive Uniform(.8,1.2) draw. This temporary array is NOT the canonical input. Copy its upper-triangular float64 entries once, in increasing (i,j) order, to both P[i,j] and P[j,i], normalizing signed zero to +0. Reject nonfinite values. Certify the exact serialized dyadic-rational P by unpivoted rational LDL: each pivot is computed with Fraction.from_float for the stored values and must be strictly positive. n<=32 for every such dense PD constructor in this plan. A failed certificate is a generator/construction failure which stops the dataset, never a resampling opportunity, method incompatibility or diagonal shift. The canonical symmetric P and certificate are written before any consumer sees it. The peak and separable consumers receive the same exact bytes; neither old validator is changed.

N07 deliberately uses an axis-aligned diagonal PSD constructor instead of rounded orthogonal mixing: draw a seeded permutation of coordinates, place r strictly positive finite float64 values `Uniform(.8,1.2)*geomspace(1,10,r)` on its first r diagonal coordinates, and exact +0 elsewhere. Each serialized positive diagonal is an exact positive dyadic rational, so exact rank=r and PSD follow by inspection. This rank-control population does not claim rotation-invariant low-rank coverage. No approximate eigensolver decides its rank and no near-zero rounded eigenvalue is clamped. All other new Hessians are strictly PD: MPC mirrors one upper triangle of its computed condensed quadratic and passes the same exact rational LDL certificate (n20), while thermal Hessians are exact positive diagonals. The no-diagonal-shift rule applies to every constructor.

Generic random row constructor draws a Uniform(0,1) mask below the declared density and independent normal values divided by sqrt(max(1,density*n)); this is a generator choice, not sensor noise. First n rows of applicable hard-box families are exact identity; only remaining rows are random. Store actual achieved density/condition, not the nominal target as a measured value. Requested condition/rank and certified serialized condition/rank have separate fields; PD condition is a floating diagnostic, while exact PSD/rank certificates use the rules above. Pure mirrored-PD, exact-diagonal-PSD and deliberately indefinite algebraic witnesses must pass before registration. The rejected unsymmetric QR and near-zero-eigenvalue witnesses remain in rejected-design-2026-11-05-r1/independent-audit.json.

Default separable costs per finite soft side are linear.3 and quadratic2; a stated side-price ratio scales both upper coefficients relative to lower. Hard rows have no soft costs. All default hard boxes are[-2,2]. For a finite-width generic soft interval, draw center Uniform(-.1,.1) and half-width Uniform(.3,.6), independently per row. Generic linear q has iid Normal(0,3) entries. Regime multipliers apply after the underlying draw. A fully unbounded side has no penalty coefficient or epigraph variable. Record finite masks and original units at ingestion.

## Families N01 to N08 and N11/N15

- N01: draw scalar curvature Uniform(.8,1.2), lower Uniform(-1.1,-.9), upper=lower+2. Set target=lower-r, where r is the registered distance multiplied by Uniform(.95,1.05), and q=-P*target. Both interval sides are soft at default symmetric costs.
- N02: same independent draws, target=upper+r; upper/lower cost ratio2. No old N01 draw is reused.
- N03: n2,m4; PD constructor with kappa5; `A=[I;I]`. First2rows have lower=-infinity and upper=-gap/2; last2 have lower=gap/2 and upper=+infinity. All finite sides are soft L1linear.3 with zero quadratic cost. q is the generic draw. This includes exact-gap0 and conflicting positive-gap controls without ever giving an individual interval lower>upper.
- N04: n2,m6; PD constructor kappa5. A first2rows I, hard[-1,1]; last4rows normal dense as defined above with independently drawn default soft intervals. q is the generic draw multiplied by registered demand multiplier. Default positive elastic costs on soft rows.
- N05: n8,m24; PD constructor kappa10, first8hard identity rows[-2,2],16random dense soft rows with default intervals. Four consecutive disjoint groups of4soft rows each, lower_scale1 and upper_scale the registered ratio, linear.5,quadratic1. q is generic. There are no separable costs attached to grouped rows and no overlapping group.
- N06: n32,m80; PD constructor kappa10, first32hard identity rows, remaining48random rows at the registered density and default intervals. Default symmetric costs. Sparse structure is exported from the generated exact matrix, including its explicit coordinate mask; density is not silently made equal to the nominal setting by dropping important rows.
- N07: n16,m40; exact diagonal/permuted PSD constructor of registered rank, as above. First16hard identity rows and24dense soft rows, default symmetric elastic costs. Hard box ensures a bounded optimum even when r0 and q nonzero. Singular solutions are compared by objective/KKT, not arbitrary equality of a nonunique primal optimum.
- N08: n32,m80; PD constructor at registered kappa, first32hard identity rows,48random rows at density.2, default soft intervals, upper/lower cost ratio2. All scaling remains in original input; normalization for checks is separately recorded.
- N11: n8,m24; PD constructor kappa10; `A=[I;I;I]`. First8rows upper=-gap/2 with lower-infinity; next8rows lower=gap/2 with upper+infinity; final8rows interval[-1,1]. All finite rows are soft with L1linear.3 and zero quadratic cost. q is generic. These contradictions test restoration/elastic semantics without creating an infeasible hard set.
- N15: n16,m40; PD constructor kappa10; first16hard identity rows[-2,2],24random rows density.2 and default soft intervals. Both finite-side linear coefficients.3 and quadratic coefficients `.3*registered_ratio`; symmetric sides. q is generic.

All generated finite intervals remain ordered. Fully free, hard-infeasible, indefinite-P, zero-price, extreme-overflow and unsupported-group controls are small named engineering/scientific negative controls outside these scoreable draws and must be retained with their expected refusal/status; they are not used to inflate the nominal regime count or train labels.

## N09, N10 and N12 double-integrator model

State s=(position[m],velocity[m/s]), sample dt.2s, horizon20. Draw source mass m Uniform(.8,1.2)kg, state weights w_position Uniform(2.7,3.3), w_velocity Uniform(.27,.33), force weight w_force Uniform(.09,.11). Dynamics are `s_next=F s+B u`, `F=[[1,dt],[0,1]]`, `B=[dt²/(2m),dt/m]`, force u inN. Form the exact condensed G/offset over20steps, `P=G' W G+w_force I`, `q=G' W offset`. Hard force bounds are[-1,1]N, soft velocity bounds[-1.5,1.5]m/s. Dynamic equations are identities of the condensed representation, not softened constraints. Comfort position bounds are[-limit,limit]m. Side costs are recorded in consistent objective-per-unit and objective-per-unit² coordinates; lower linear.3/quadratic2, upper ratios as below. The objective is a synthetic normalized operating cost, never a physical currency.

N09 has initial position equal to the registered value multiplied by Uniform(.95,1.05), velocity Uniform(-.1,.1), limit2m, symmetric costs. N10 has initial position Uniform(1.14,1.26)m, velocity Uniform(-.1,.1), registered limit, upper/lower cost ratio2. These source mass/weights and input parameters are disjoint across splits. There is no hidden safety-certification claim.

N12 has the same source model, initial position Uniform(.8,1.6)m and velocity Uniform(-.1,.1)m/s, limit.4m, upper/lower cost ratio2. Generate32fixed shared QP inputs along a method-independent reference trajectory. At frame8 add +r to velocity, at20 add-.75r, with registered impulse amplitude r. Post-impulse state is used to formulate that frame's QP. The reference forcing law is `u_ref=clip(-.5*position-.2*velocity,-1,1)`N, held for dt; then advance the exact dynamics. All methods see the same32states/inputs. Candidate first actions are evaluated/replayed but never fed back to create method-dependent benchmark inputs. This is a shared-input MPC forecast stream, not a candidate closed-loop controller qualification. Store pre-impulse, post-impulse, reference held force and next-before-impulse state distinctly; no diagonal interpolation of held force. Full trajectory is one split/bootstrap unit.

## N13 and N14 authored thermal model

Use a new independently drawn, explicitly authored two-zone RC forecast model, not the historical C13 battery/grid byte stream or a claim of reproducing its full scope. Each zone is independent with hard hourly dynamics `T[k+1]=a*T[k]+b*heat[k]+(1-a)*outside[k]`, horizon16,2zones. Draw retention a Uniform(.88,.94), heater gain b Uniform(.22,.30)degreeC/kWh and phase Uniform(0,2pi), one draw per zone. Initial temperatures are `21.5+.5*sin(phase)`degreeC. Outside forecast is `8+3*sin(2pi*(hour+offset)/24)`degreeC, with offset drawn Uniform(0,24)h per source unit. Heating is hard[0,6]kWh per hourly interval. Comfort bounds are soft[21,23]degreeC for future temperature rows. Variables are34temperatures and32heating values; hard dynamics34rows, hard heating32rows and soft comfort32rows. Store the actual66-variable/98-row sparse system and unit map.

Base Hessian diagonal is.002for temperatures and.04for heat; q_temperature=-22*.002, q_heat=`.2+.08*sin(2pi*(hour+offset)/24)`synthetic currency/kWh, repeated per zone. Constants omitted from this quadratic objective are explicitly common to all methods and not reintroduced in only one evaluator. Feasibility of hard dynamics/heating follows the zero-heater rollout; comfort may conflict and is intentionally soft. This model is a forecast optimization, not a coupled building/battery/grid field system.

N13 attaches one disjoint16-row comfort peak group per zone, lower_scale1,upper_scale1.5, linear=`5*registered_multiplier`,quadratic1. N14 uses separable comfort costs lower_linear.3,lower_quadratic.4 and upper coefficients scaled by the registered upper/lower ratio. Both retain all hard dynamics/heater rows. The source is the authored RC equation/model pattern in product `data-pipeline/pipeline/coupled_cases.py` at the frozen implementation pin, with fresh entropy and outputs. The broader historical energy model and its MIT attribution remain in product history; this new model must not borrow that provenance as if it were the same dataset.

## Exact representation and leakage checks

Each draw serializes the raw mathematical input before lifting. Store source parameters, coefficients, units and generator-source digest alongside matrices. No use of method names, timing outputs, label distributions or held-out success affects a generator draw. Domain-matrix source unit is the source grouping key; shared shape, published equation or fixed horizon is not a shared sample. Separate fresh coefficient seeds prevent source-model leakage. Check both canonical input hashes and semantic parent/source ancestry, not just filenames.

L2WS dynamic features use a fixed full coordinate layout for each shape: upper-triangular P in row-major triangular order, dense row-major A values, q, lower and upper bound values with zero for absent sides, then lower and upper finite masks. Sparse inputs are not reduced to an untracked list of nonzeros. Exact fitted normalizers, loss/output units, source weights, graph statistics and seed allocation are in learning-spec.md. Actual P/A and bounds are also passed independently to the differentiable operator; normalized features do not change the solved mathematical problem. GNN input remains the sparse weighted graph with explicit coordinate/equality maps. The fourteen predeclared MLP shapes and all graph shapes are in semantic-matrix.json; there is no post-data choice of easy heads.

Before registration, source tests must prove generation determinism, all exact counts, physical dynamics/units, hard feasibility, PSD/PD conditions, fresh source blocking, input hash preservation through the loader and method-independent temporal inputs. Any correction needed to these proposed equations returns to independent design review before candidate generation. No generated result is available yet.
