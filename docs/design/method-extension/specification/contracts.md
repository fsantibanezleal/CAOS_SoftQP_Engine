Prospective design only. Paths below are proposed producer/consumer ownership, not claims those files or schemas already exist. ## New scientific boundaries

Common envelope: schema ID and version, protocol_id/protocol_sha256, source_lock_sha256, content identity, exact provenance; all hashes lowercase64hex. JSON is strict: no NaN/Infinity, numeric bool coercion or duplicate keys. Infinite bounds use null plus explicit finite masks with unambiguous lower/upper meaning. Every array has a dimension declaration and exact length/index shape checks. Paths are safe relative paths under configured external roots, no absolute paths, traversal, URL-as-local-path or symlink escape. A syntactically correct recomputed outer hash cannot authorize changed scientific semantics.

R2normative attachments are numerical-spec.md, learning-spec.md, timing-spec.md, recovery-spec.md, normative-rules.json, semantic-matrix.json and negative-controls.json. The protocol binds their exact hashes, the canonical PD/PSD/rank recipe and all expected compressed keyset hashes. These are definitions awaiting independent review, not implemented schemas. The protocol cannot accept one prose source while substituting a different machine rule.

The input stores canonical symmetric P bytes plus exact certificate type/rank/pivots (or exact diagonal support), pre-canonical temporary-constructor diagnostic, requested condition and diagnostic actual condition. Exact LDL rejection is a construction failure, not method incompatibility. Existing peak/separable validators and old certificates are unchanged. The feature/checkpoint boundary stores head ID, complete ordered coordinate/row mapping, dimensions, float64 parameter dtype, source-weighted train normalizer and per-parameter initialization streams. It refuses a missing required head before training, rather than selecting an easy shape subset.

Each method-result stores raw original x/y, precisely domain-repaired ybar, raw/repaired stationarity, original objective components, H/G/K/F/F_all/D and exact unit scales, raw native candidate flag, all oracle objectives/settings/acceptance, weighted peak-side lambdas/t/mu/group stationarity when applicable, actual injected state, every timing phase/retry/reset, and its complete method/seed/source/frame/repetition key. Oracle y never enters candidate metrics. Undefined statistics are null with a required reason; they are not0or NaN. Evaluation stores the exact compatible/incompatible/failed keysets, family/regime/source/seed weights, per-source trajectory totals and crossed-bootstrap settings/draw receipts; any primary compatible failure gives null estimate/interval and false acceleration qualification.

Model registry has two new real slots, not surrogate placeholders: `learned_osqp` and `learned_daqp`. Each slot identifies architecture/input/output feature contract, source/license, version, training/calibration IDs, checkpoint, complete held-out metrics, declared offline lane and replay export. Deterministic methods have no fake training checkpoint. A checkpoint counts only when its actual reader and inference calls are verified. New result/index contracts are separate versioned boundaries rather than changing old frozen JSON in place. If an existing shared schema is extended, semantic version/history rules apply and its old-version consumer remains supported for old files.

## Typed pipeline responsibilities

`ingest` validates file hashes, formulation, calibration, units and provenance. `preprocess` canonicalizes and validates sparse indexing/symmetry without changing the objective; produces a reversible transform/mapping. `dataset/split` enforces source blocking and exact manifests. `features` constructs actual matrices/graphs and fitted training-only scales. `train` computes gradients and updates weights with source-bound resume. `infer` performs the actual learned initialization and official solver call. `evaluate` independently recomputes original metrics/acceptance and full-cost statistics. `export` writes the tested numeric model/replay subset with hashes. `validate` replays every identity/dimension/compatibility/output acceptance check and expected matrix from saved artifacts. Each responsibility has a typed dataclass/schema, CLI configuration and real failure path; none is an empty wrapper printing the next command.

## EARS requirements proposed for root integration

- LC-001: WHEN an unreviewed or hash-mismatched protocol is supplied, the scientific entry point SHALL refuse before generation, training or inference.
- LC-002: WHEN an output resolves inside either checkout, a frozen study or an unowned active job, the CLI SHALL refuse before writing.
- LC-003: WHEN training/test source or parent IDs overlap, the split validator SHALL fail and list the colliding identities.
- LC-004: WHEN a feature vector contains label, test-statistic, invalid mask or inconsistent coordinate order, the feature consumer SHALL refuse it before network execution.
- LC-005: WHEN a matrix is nonconvex or an exact epigraph is unsupported, the adapter SHALL refuse without silently shifting curvature or replacing the declared penalty.
- LC-006: WHEN a finite hard row is present, every accepted solver result SHALL preserve and independently validate that exact row.
- LC-007: WHEN a learned initialization is requested, the inference path SHALL call the actual source-bound network and inject its prediction into the declared real solver.
- LC-008: WHEN L2WS training differentiates through K steps, the implementation SHALL use the source-bound operator and pass independent value/gradient and stock-initialization parity checks.
- LC-009: WHEN graph constraints are permuted consistently, probabilities and recovered results SHALL transform equivariantly within registered tolerances.
- LC-010: WHEN the graph predicts an inconsistent working set, initialization repair SHALL preserve equality flags, terminate within its registered bound and include every retry in total cost.
- LC-011: WHEN a native backend reports success, the consumer SHALL independently validate original objective, hard rows and stationarity/subgradient/complementarity before emitting accepted state.
- LC-012: WHEN a missing checkpoint, package or consumer is encountered, readiness SHALL report missing/partial rather than available or mathematically incompatible.
- LC-013: WHEN training resumes, source/protocol/split/architecture/checkpoint identities SHALL match and deterministic fixture results SHALL agree with uninterrupted training.
- LC-014: WHEN public inference reads weights, it SHALL admit only the declared numeric architecture/parameter representation and reject executable checkpoint objects.
- LC-015: WHEN evaluation computes a matrix, every required source/frame/method/seed/repetition cell SHALL have one status; missing and duplicate cells SHALL fail completeness.
- LC-016: WHEN a failed compatible or oracle cell exists, its identity and failure SHALL remain in the published denominator and scientific acceptance SHALL fail as specified.
- LC-017: WHEN computing temporal uncertainty, all frames of a source trajectory SHALL remain a single resampling block.
- LC-018: WHEN a browser build or deployment runs, it SHALL validate existing exports and SHALL NOT generate data, train or regenerate benchmark truth.
- LC-019: WHEN an N-case is selected, the workbench SHALL read that case's admitted method artifact, display its lane/units/provenance and propagate linked row/frame selections.
- LC-020: WHEN a learned method has no completed held-out results or replay consumer, product completeness SHALL fail even if its import, selector and checkpoint exist.
- LC-021: WHEN preparing a public release that changes methods/results, the technical report SHALL be updated in the authoritative native LaTeX template and independently reviewed before or with the release.
- LC-022: WHEN any new stage/method/model contract is added, EN/ES notebooks and their actual-tool coverage map SHALL cover it with executed worked examples at the current content bar.
- LC-023: WHEN a new comparison is produced, the two historical campaign inputs, registered endpoints, numerical outputs and negative conclusions SHALL retain their immutable identities.
- LC-024: WHEN environment admission has only wheel metadata evidence, status SHALL remain unverified until real isolated import, solver, gradient and PyG-step checks pass.
- LC-025: WHEN a new canonical float64 Hessian lacks exact symmetric PD/PSD/rank certification, generation SHALL stop without diagonal shifting, resampling or recoding failure as method incompatibility.
- LC-026: WHEN evaluating a result, the consumer SHALL use numerical-spec.md equations and fixed canonical unit scales, including raw and precisely repaired duals, and SHALL reject a different normalization despite a recomputed outer hash.
- LC-027: WHEN any of the three predeclared references fails tighter acceptance or objective agreement, every candidate for that source/frame SHALL retain oracle-failed state without reference substitution.
- LC-028: WHEN building labels/losses, the learner SHALL apply the exact dimensionless loss transition, mask/tolerance/class-weight/graphwise-statistic/source-trajectory reduction rules in learning-spec.md.
- LC-029: WHEN seeds41001/41002/41003initialize models, all random parameters SHALL use the registered local streams overriding constructor123and SHALL have reproducible distinct initial bundle hashes.
- LC-030: WHEN any of fourteen required MLP heads or an eligible graph shape is absent, training/model completeness SHALL fail; no post-data easy-shape exclusion is allowed.
- LC-031: WHEN validating held-out artifacts, expected_inventory.py's exact status/control/seed/repetition/reference/label keyset SHALL match with no missing, duplicate or extra keys, and incompatible keys SHALL have no timed repetitions.
- LC-032: WHEN any primary compatible candidate/control/reference fails, the primary estimate and interval SHALL be null and acceleration qualification false, with every failure retained.
- LC-033: WHEN computing primary acceleration, the evaluator SHALL use ratio-of-summed-frame-median costs and the exact equal-family/regime/source/seed mean/crossed-bootstrap/quantile/decision in timing-spec.md.
- LC-034: WHEN recovering a peak result, the consumer SHALL use cU*lambdaU-cL*lambdaL plus explicit t/group stationarity, and SHALL preserve the exact old symmetric/asymmetric free-row lift behavior.
- LC-035: WHEN checkpoints rotate, only owned source-bound latest states may be replaced atomically; initial/best/final states and all history/hash receipts SHALL remain, within the registered retention budget.
- LC-036: WHEN any R2design/checker succeeds, status SHALL remain prospective until separate independent review and actual contract/runtime/scientific acceptance; no design check grants campaign or release acceptance.

## Narrow R3 diagnostic and byte-authority closure

NC19/NC20define zero-side and zero-group prices with finite correct original optima; NC21defines finite input coefficients whose named transform/candidate evaluation overflows float64; NC22defines a hard-only convex unbounded objective with an explicit recession certificate rule. Each new typed fixture has complete dimensions, finite masks, units, target-specific outcomes and exact diagnostic keys. The24fixtures have101target/seed status keys, with zero timed repetitions and no inclusion in primary/train populations. Unresolved certificates remain control failures, never accepted finite optima or passed negative controls.

Every emitted normative JSON/Markdown/receipt uses UTF8with LF explicitly and hashes actual read_bytes. Historical rejected snapshots retain their exact original bytes, including the stale R2receipt; its CRLF-derived old digests are not reasserted as current identities. check_plan.py and validate_sources.py default to read-only validation. Explicit candidate receipts are emitted only to external --output paths, then frozen by a separate deliberate copy; expected_inventory.py distinguishes explicit production --output from read-only --check. Verification never repairs or rewrites the authority being checked. The final manifest is produced after sources/keysets freeze and must pass two byte-idempotent read-only checks plus source/receipt mutation refusals.

Public unbounded/dual-infeasible status requires independent exact rational arithmetic on the submitted canonical float64 dyadics: exact PSD, feasible anchor, finite nonzero normalized direction, Pd=0, q'd<0and all finite-bound recession signs.
