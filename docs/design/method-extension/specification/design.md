# Prospective SoftQP method and learned-model completion design

Date: 2026-11-05. Status: proposed for independent review, not implemented or scientifically accepted.

## Decision and exact boundary

The global product bar requires ten to twelve genuinely distinct methods and two trained learned methods. The current seven deterministic methods do not satisfy that bar. Complete the ladder with Clarabel, ProxQP, PIQP, an OSQP learned fixed-point warm start, and a graph-predicted DAQP active-set warm start. These are five substantive algorithmic verticals, not penalty variants. The two learned methods have different representations, targets, learning objectives and downstream algorithms. Their networks must actually be trained, persisted and evaluated. A row, import, pretrained architecture or fallback-only faÃ§ade does not count.

No method in this addition is claimed as an original scientific contribution. The existing AAGSP and directional studies remain completed negative work. This new protocol does not reopen or retune either endpoint. New results may also be negative. The update requires a current technical-report version, preserving the separate historical research manuscript and its conclusions.

## Exact mathematical transformations

For separable intervals, bind the unchanged `softqp.lifting.lift_problem` and `reference.lift` ordering described in recovery-spec.md. The symmetric path uses one shared relaxed-row slack (or one signed pure-quadratic slack), including its existing redundant slack for an entirely free soft row. The asymmetric path instead emits one nonnegative slack per finite soft side and no slack for an entirely free soft row. These exact existing representations are not silently canonicalized into the same shape. Original objective is base quadratic plus separate lower/upper linear and half-quadratic violation costs, with hard rows unchanged. No Hessian shift, finite replacement of infinity or cost clipping is permitted. New Hessians follow the exact symmetric assembly/PSD/rank certificates in generator-spec.md; old consumers and certificates are untouched.

Carry the lift's original-row map through each solver conversion. For finite hard intervals, Clarabel uses one nonnegative-cone row per finite side; a lower row is negated, an upper row is unchanged, and equalities use a zero cone. Recover the interval dual as upper multiplier minus lower multiplier, summing into the original row, then use the lift's recovery. PIQP and ProxQP split exact equalities into the equality block, retain interval inequalities, and recover `z_u-z_l` or the backend's signed interval multiplier respectively. Validate original objective, hard rows, stationarity and side complementarity independently. All free rows, empty equality blocks, one-sided rows, hard equalities, mixed scales, PSD Hessians and absent soft rows are adversarial cases.

For disjoint group peak, bind the exact existing epigraph ordering and weighted recovery in recovery-spec.md: one nonnegative t per live group, finite side inequalities, cost a*t+b*tÂ²/2, hard ungrouped rows. Original signed row dual is `c_U*lambda_U-c_L*lambda_L`; group stationarity additionally includes the t>=0 multiplier. Never recover an unweighted side sum. Symmetric separable costs on ordered intervals are included for directional projection through one singleton group per soft row: at most one side violation is positive, so the max equals the separable violation. General asymmetric linear/quadratic ratios do not automatically admit that conversion. The complete pre-data semantic table specifies these exact mappings. Existing code/artifacts remain untouched; no non-QP norm is approximated.

## Learned fixed-point method

One MLP bundle contains a shape-specific head for each supported lifted shape. A head is not a separate method. Inputs contain the actual upper-triangular Hessian, full fixed-coordinate constraint matrix values, linear term, finite bounds, finite-side flags and declared physical scaling; generator-spec.md fixes their exact order. Fit normalization on training only. Distinct matrix/source seeds are blocked across splits; dynamic matrices are passed to the exact differentiable step and factorization, rather than inferred from a family name. Unseen shapes refuse explicitly. This is a known-shape, variable-coefficient adaptation, not an unseen-size generalization claim.

Use float64 mathematical steps. Let `w` denote the interval auxiliary variable and let `K=P+sigma I+A' R A`, with positive `sigma` and positive diagonal `R`. Starting from MLP `x0,y0`, initialize `w0=A x0`, as in the captured authors' `k_steps_train_osqp` implementation. Each unrelaxed step solves `K x+ = sigma x-q+A'(R w-y)`, projects `w+=clip(A x+ + y/R,l,u)`, then sets `y+=y+R(A x+-w+)`. Fix `alpha=1`, `sigma=1e-6`, scalar `rho=0.1`, `rho_is_vec=False`, scaling0 and adaptive-rho off for the matched learned/cold control. Validate the initialization and every step against the separately implemented mathematical reference and stock C OSQP before training. The parity gate must inspect the actual installed stock binary's initialized workspace behavior, including equality-row rho handling, rather than assume equality from final optima. The requested Python package version need not be its C-core tag; an attempted C-repository v1.1.3 lookup returned404 and is not accepted source provenance.

The fixed-point network has two128-wide ReLU hidden layers and a linear n_lift+m_lift output. learning-spec.md fixes float64 parameters, output-state scaling, the exact final-transition K=5 loss, all fourteen heads and source/frame weights. The squared loss/framework are documented adaptations, not an inherited theorem or the authors' runtime. No supervised solution target enters that loss. Inference predicts initialization and calls real stock OSQP through public warm_start(x,y); it never returns the network prediction as an accepted QP solution. Feature assembly, inference, injection, solve and validation are all measured. K0/zero-network diagnostics do not count as methods.

## Graph-guided active-set method

Use the exact hard lifted QP and expand finite intervals to one-sided inequalities; equalities retain their immutable flag. This makes the graph's mathematical input match the published QP setting. Require positive definiteness of the actual lifted Hessian; L1 epigraphs with zero slack curvature and PSD original Hessians are prospectively incompatible. No small diagonal may be added to make them pass. The paper's scope is PD; extending its proximal behavior would be separate reviewed work.

Construct variable and constraint nodes, node features linear cost/bound/equality indicator/type, Hessian edges and both directions of constraint-coefficient edges. Include slack variables and all hard bounds. Zero/infinite data are represented through explicit masks/removal, never an arbitrary numerical big-M. Use the official three-layer LEConv width128 structure, LeakyReLU0.1, LayerNorm and sigmoid, preserving attribution. Variable outputs are masked out of the classification loss and metrics. This differs from portions of the upstream experiment implementation, which include variable labels in BCE; the adaptation is explicit. Weighted BCE class weights use training labels only; no per-test population normalization or label information enters features. Graphwise feature normalization is deterministic and independent of labels; single-node standard deviations must be finite.

learning-spec.md fixes exact label tolerances, ambiguity/equality masks, class weights, graphwise population standard deviations, graph/source/trajectory loss reductions and threshold selection. It also overrides upstream manual_seed(123) constructor behavior: all three registered seeds must have distinct reproducible initial parameter hashes and source-bound RNG receipts. Labels use a cold DAQP solution passing the numerical-spec.md oracle/KKT rules. Equality flags survive prediction and repair. Remove the least-confident predicted inequality, row-ID tie-break, on rank-inconsistent initialization for at most the initial predicted inequality count; at most one final recorded cold solve. Invalid scores/shape/checkpoint reject. Every retry/fallback is measured and actual injected flags are recorded; ignoring every prediction is not implementation.
