# Official method-extension comparators

The prospective engine supports Clarabel 0.11.1, ProxSuite's sparse ProxQP 0.7.2 and PIQP's sparse solver 0.6.4 as distinct methods. Select `clarabel`, `proxqp` or `piqp` through `softqp.solvers.solve` or `softqp.sessions.PreparedSolver` for separable rows. For disjoint directional peak groups, pass the same method names to `softqp.solve_peak` or `softqp.PreparedPeakSolver`. Install the exact dependencies using the independently bound CPU profile. Each adapter uses the settings listed in the [timing specification](specification/timing-spec.md), including a single Clarabel thread. The original SDK defaults and method names keep their existing behavior.

The comparators consume canonical float64 CSC sparse matrices and float64 interval vectors. Ordered hard intervals and absent sides use the original semantics. The engine lifts separable rows using the existing symmetric or asymmetric transformation and grouped rows using the existing peak epigraph. Optional numeric reference magnitudes `variable_units`, `row_units`, `peak_units` and `objective_unit` define the canonical normalization and default to one in each caller-declared canonical unit. Applications validate physical dimension labels and unit provenance. The returned primal, signed row duals, objectives and violations use the submitted physical coordinates. Negative duals correspond to the lower side and positive duals to the upper side. Peak recovery applies the original directional coefficients and retains side multipliers, peak values and the supplemental epigraph checks.

Prepared comparator calls validate updates to `q`, `lower` and `upper` before replacing the previous snapshot. The finite-side pattern and hard equality classification stay fixed. Every solve creates an official cold backend as required by the registered per-frame lifecycle. `workspace_reused` is false and `reset()` has no solver state to clear. Cold `elapsed_seconds` includes initial validation, the lift and recovery. Prepared results expose separate setup and update wall times alongside native setup and solve wall times.

A `candidate` has the allowlisted native success status and passes the independent original-space H, K, F, F_all and D checks, plus epigraph checks where applicable. `accuracy-rejected` retains any finite diagnostic candidate while exposing a failing status. `backend-unavailable`, `native-failure` and `inconclusive` carry separate reasons. A native infeasibility flag is evidence for review and remains in `native_status`. Only an exact hard-QP recession certificate can promote an unbounded-like native status to public `unbounded`. An optional `recession_certificate=(anchor, direction)` supplies a proposed physical-coordinate proof. The checker proves PSD using exact dyadics for diagonal Hessians and connected blocks of at most 32 variables. Larger coupled blocks can remain inconclusive. All finite-bound recession signs, anchor feasibility, null curvature, strict descent and normalization must be exact. The public reader also applies the R4 numerical screens to the normalized problem. The automatic search checks a zero anchor, a native ray where available, and the scalar objective direction when the library does not expose a ray.

`softqp.comparators.oracle.reference_objective` independently runs stock OSQP 1.1.3, Clarabel 0.11.1 and PIQP 0.6.4 at the specified tighter thresholds. All three must pass and agree before it returns a median objective. The registered product runner supplies the external source, lock identities and execution budgets, combines candidate metrics with the objective gap, and owns scientific acceptance. Historical SDK experiments remain separate from this prospective path.
