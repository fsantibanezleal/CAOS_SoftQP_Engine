# Requirements for the prospective method extension

Status: implementation pending. This source unit follows independent design review on 2026-11-05. It introduces three official numerical backends and two trained initializers. None is counted as an implemented product method until its complete vertical passes. Existing 0.2.0 interfaces and both historical negative studies remain preserved.

The accepted design manifest is `e098010809f8b4cbb57f04e70279bf0b3f4aa90994be8a1ae022bbb52a4c7fb0`; its independent review is `3738e25295f950cacfcef2dc723bbef5cc3416260d3541354b30b204327e2262`. This records design acceptance only. Test paths below are implementation obligations, not assertions that those tests already exist or pass.

| ID | Requirement | Required gate |
|---|---|---|
| ME-001 | WHEN an extension input is admitted, THE engine SHALL reject nonfinite values, non-exact matrix symmetry, invalid dimensions, invalid sparse indices, reversed bounds and negative prices before a backend is called. | `tests/extension/test_contracts.py` |
| ME-002 | WHEN a supported original problem is transformed, THE engine SHALL retain a source-bound map of every original variable, row, finite side, auxiliary and dual sign, without changing the original objective. | `tests/extension/test_transform.py` |
| ME-003 | WHEN a transformed result is recovered, THE engine SHALL recompute the original objective, row values, side departures, hard feasibility and applicable optimality residual independently of the backend. | `tests/extension/test_recovery.py` |
| ME-004 | WHEN Clarabel, ProxQP or PIQP is selected, THE engine SHALL execute the pinned official implementation with declared settings and report every failure or incompatibility with its original source identity. | `tests/extension/test_backends.py` |
| ME-005 | WHEN a numerical status suggests an unbounded original hard QP, THE public status reader SHALL require independently checked exact rational PSD, anchor feasibility, a normalized nonzero nullspace ray, negative objective slope and all recession signs before exporting unbounded. | `tests/extension/test_certificates.py` |
| ME-006 | IF a numerical unboundedness screen passes without that exact certificate, THEN THE engine SHALL retain an inconclusive or refused status and SHALL NOT declare the original problem unbounded. | `tests/extension/test_certificates.py::test_tiny_dyadic_bounded_counterexamples` |
| ME-007 | WHEN the learned OSQP method is trained, THE engine SHALL differentiate the prescribed float64 five-step fixed-point map and sixth transition residual, using the declared source-weighted loss and training-only normalizer. | `tests/extension/test_fixed_point.py` |
| ME-008 | WHEN the learned OSQP initializer is applied, THE engine SHALL initialize the real public stock OSQP solver through its supported warm-start interface and retain network, transform and solver identities with the complete inference cost. | `tests/extension/test_learned_osqp.py` |
| ME-009 | WHEN graph-guided DAQP is trained or applied, THE engine SHALL use the declared variable/constraint graph, exact LEConv architecture, ambiguity masks and calibration policy, with explicit per-run seeds and bounded active-set repair. | `tests/extension/test_graph_daqp.py` |
| ME-010 | WHEN a learned checkpoint is read for public inference, THE reader SHALL accept only numeric arrays and declarative architecture metadata with verified hashes, shapes and provenance, and SHALL reject executable pickle objects. | `tests/extension/test_checkpoints.py` |
| ME-011 | IF a checkpoint, normalizer, calibration, transform or input identity differs from the registered identity, THEN inference and resume SHALL refuse rather than silently substitute a default model or restart under the old identifier. | `tests/extension/test_checkpoints.py` |
| ME-012 | WHEN a compatibility cell is classified, THE engine SHALL distinguish a mathematical precondition failure from a missing runtime, missing model, timeout, native failure or accuracy rejection, and SHALL retain the declared method in the complete matrix. | `tests/extension/test_compatibility.py` |
| ME-013 | WHEN a run is timed, THE engine SHALL include validation, transformation, model loading or amortization, feature computation, inference, repair, native setup/solve and original-space evaluation according to the frozen timing specification. | `tests/extension/test_timing.py` |
| ME-014 | WHEN a job starts or resumes, THE orchestrator SHALL enforce external source-bound output roots, one CPU worker and single-thread numerical libraries, declared memory/disk/deadline limits and atomic resumable progress. | Product orchestration tests and `tests/extension/test_paths.py` |
| ME-015 | WHEN any new method is admitted, THE independent reviewer SHALL verify its actual source, mathematical transformation, dependency/license lock, executable tests, real production path and retained failure controls before prospective data generation or training registration. | Independent implementation admission receipt |
| ME-016 | WHEN the extension is evaluated or published, THE pipeline SHALL preserve both completed historical negative studies and SHALL export every newly registered key, failure and denominator without retuning those historical endpoints. | Product expected-keyset and historical-payload adversaries |

No optional import, selector label, parameter variant, fabricated checkpoint or fallback-only adapter satisfies these requirements. Separate algorithmic methods remain separately identified even when an implementation shares a transformation or an original-space checker.
